# 154 — Perplexity Search backend (2.14.0)

Baseline 2.13.20 (`836c812`, 296 tests). Final **299/299**.

## Authority

- Official endpoint and OpenAPI: <https://docs.perplexity.ai/api-reference/search-post>
  (`POST /search`, Bearer, `query` string or 1-5 array, `max_results` 1-20
  for `web`, `search_type` `web`, domain include/exclude, recency
  `hour|day|week|month|year`, `search_language_filter` ISO 639-1).
- Overview: <https://docs.perplexity.ai/docs/search/overview> (ranked pages,
  not a generated answer).
- Result fields: `results[].{title,url,snippet,date,last_updated}`;
  `date` is YYYY-MM-DD, normalized to ISO by the shared provider pass.

## Implementation

- `lib/backends/perplexity.js`: REST POST, Bearer auth, `max_results`
  clamped 1-20, recency/language/domain filters, 401/402/429/5xx mapped by
  `webErrorFromResponse`, no generated answer concatenated.
- Registered last in `BACKENDS` so default fan-out order is unchanged; it is
  key-gated and off by default. Config: `enablePerplexity`,
  `perplexityApiKeyEnv`, `perplexityBaseURL`; Settings card gets a keyed card.
- Cache key fields are automatic (`backendCacheKeyFields`), health/breaker
  work by backend id, and `ready()` requires a resolvable key.

## Verification

- Request-shape/auth/filter test, parser drop/cap test, missing-key test.
- No live Perplexity request: no `PERPLEXITY_API_KEY` is present on this host;
  behavior is covered with mocked HTTP only.
- Existing providers unchanged; full suite and live Exa/Parallel still pass.
