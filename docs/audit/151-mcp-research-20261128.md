# 151 — search/MCP research and polish (2.13.18)

Baseline 2.13.17 (`ad6f739`, 267 tests). Final **281/281**.

## Official research

- DSH web seam: one query per request; `maxResults` is owned by
  `dsh-tool-web` (default 10) and the seam truncates + sets `truncated`;
  providers are thin adapters (`/opt/dsh-0222/.../dsh-web/src/types.ts`,
  `docs/subsystems/web.md`).
- `dsh-tool-web` default `searchTimeoutMs=30000`; a configured
  `backendTimeoutMs` above that is pre-empted by the host's tool timeout.
- Official MCP client: stable `mcp__server__tool` names, `tools/list`
  discovery/pagination, generation swap, per-call 60s deadline, cancellation,
  reconnect and close (`docs/subsystems/mcp.md`,
  `/opt/dsh-0222/.../dsh-mcp-client/README.md`).
- Skill is an on-demand instruction body, not a capability; search must remain
  a tool. Wrapping search in a skill adds catalog cost without adding a
  provider. See `docs/subsystems/skills.md`.
- Provider metadata: `title`, localized `description`, optional `ready()` on
  `WebSearchProvider`; the official settings page lists provider metadata.
- Official Exa provider uses REST, requests highlights, takes the first
  highlight as snippet, drops snippetless results, and lets the seam truncate.
  Exa MCP still exposes `web_search_exa { query, numResults, objective }` and
  `Text:`/`Highlights:` text blocks.
- Parallel MCP supports `objective` + 2-3 keyword queries; Firecrawl MCP may
  return `success:false`; SearXNG public fallbacks must not receive a private
  instance key.

## Fixed

- `mcpCall` now reads SSE incrementally and returns as soon as the matching
  frame arrives instead of waiting for EOF; a server that keeps the stream open
  no longer looks like a timeout. `egress-fetch` proxy/CONNECT/forwarder paths
  now return streaming Responses (10 MiB cap enforced mid-stream, cancel
  destroys the socket) instead of buffering the whole body first; an invalid
  raw status (600-999) becomes 502 rather than throwing from an HTTP event.
- Initialize now validates the JSON-RPC error and negotiated
  `protocolVersion` before caching a session.
- `mcpText` joins every text block and falls back to `structuredContent`;
  Exa additionally accepts `Text:` and uses the first highlight. Firecrawl
  `success:false`/malformed responses become `WEB_PROVIDER_ERROR`, not a
  silent empty success.
- Session cache bounded to 64 LRU entries; cached reads refresh insertion order.
- Base URL rejects trailing-dot metadata hosts and `[::]`; redaction covers
  prefixless high-entropy keys; SearXNG never sends a private key to the
  default public `searx.be`.
- Provider picker metadata (`title`, zh/en description) added.
- Override UI: non-empty known `enabledBackends` disables and shows the
  effective switches; user-level overrides can be cleared, base-level ones
  explain where to edit. Empty/unknown lists do not override.
- `enabledBackends` override now shows a banner, disables the ignored switches,
  displays the effective set, and offers "clear override" for user-level
  overrides; base-level overrides explain where to edit.
- Keyed and optional-key cards share one badge state: a failed read is
  "read failed", not "checking" or "unset"; legacy `result.ok:false` is a read
  failure.
- Config copy now states the host `searchMaxResults` hard cap and the host
  timeout relationship.
- Exa uses the first highlight (official behavior), accepts `Text:`, and
  forwards the plan objective when present.

## Residual

- `mcpCall` still relies on the provider's abort signal; no independent RPC
  deadline or MCP `notifications/cancelled`.
- No startup `tools/list` schema probe; a server schema change is still found
  at call time.
- No `ready()` on the provider; a fully keyless-disabled/keyed-without-key
  provider still appears available.
- Session close/DELETE is not sent on plugin teardown.
- `truncated` is provider-owned approximation; seam ownership remains.
- `publishedAt` is not uniformly ISO-validated.
- The cache-key field list now lives in `resolveOptions` (`cacheKeyFields` /
  `backendCacheKeyFields`) and `CACHE_SEMANTICS_VERSION` is 3.
- Legacy hosts without `setMany` remain best-effort, not atomic.
