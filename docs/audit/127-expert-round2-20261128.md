# 127 — 2026-11-28 expert round 2 (2.9.1)

Baseline: 2.9.0 (`23d840a` / release `e9625d2`). Six experts re-audited the new
code and docs; this round integrates their P1/P2 findings. Final verification:
**218/218** unit tests, health 1/1, npm 2.9.1 published, both patches
reconstruct byte-identically.

## Findings and disposition

### Bugs / crash safety

- **P1 sync-throwing backend** (`provider.js`): `backend.search()` was evaluated
  inside `Promise.race`; a synchronous throw skipped `.finally`, left the timer
  armed, and later rejected the guard with no handler (process exit under
  `--unhandled-rejections=throw`). Fixed with
  `Promise.resolve().then(() => backend.search(...))`; a regression test now
  exercises a sync-throwing stub.
- **P2 bare IPv6 in NO_PROXY** (`egress-fetch.js`): `splitHostPort("::1")`
  treated the last colon as a port. Bare literals now keep the whole host;
  bracket form still carries a port.
- **P2 cache robustness** (`cache.js`): a transient `ttl()` error deleted a
  valid entry and could throw out of `get()`; expired reads unlinked by path
  (TOCTOU); crash-orphaned `.tmp` files were never swept. `ttl()` is now
  guarded (miss, keep the entry), expiry no longer unlinks, corrupt entries do,
  and `evict`/`clear` sweep old tmp files.
- **P2 budget-starved variants** (`provider.js`): the per-variant cap made
  ⌈backends/concurrency⌉ × budget; a leftover 80 ms was reported as a backend
  timeout alongside that backend's success. The fan-out now receives an
  absolute deadline; each backend clamps to `remainingNow`, variants split the
  remaining budget (`remaining / variantsLeft`), and a variant with less than
  2 s is not started.
- **P2 malformed backend telemetry**: the validation throw bypassed the sibling
  rejection handler; failure telemetry/health is now recorded explicitly before
  the throw.
- **P2 missing credential cooled the breaker**: a configuration error was
  folded as an outage. `WEB_PROVIDER_CREDENTIAL_MISSING` now keeps telemetry
  but skips health/breaker folding.

### Semantics / contracts

- **P1 `truncated` still wrong**: `maxResults === seamBound && ordered.length >
  maxResults`; a `numResults` preference cut is no longer seam truncation. The
  host bound is part of the cache key, because the same `min(host,user)` can
  come from different host caps.
- **P1 `keyChecking` literal**: both dictionaries now define it; the published
  2.9.0 card had shown the raw key.
- **P1 duplicate fast-fail history**: the rate-limited branch recorded twice;
  one call before the keyless split now covers both throws.
- **Cache note**: gated on `resultTelemetry`, not `resultHeader`; turning off
  the citation header no longer hides cache age in `balanced`.
- **URL canonicalization**: only protocol/host are lowercased; path case is
  preserved (`/A` and `/a` stay distinct), fragments/tracking params still drop.
- **Docs/config**: README “24 of 57 editable” fields, default timeout 24 s
  (6 s headroom under the host's 30 s tool deadline), round-robin wording
  (structural analogue of `mergeSearchResults`, not a mirror), Firecrawl
  comment, `WEB_PROVIDER_UNAVAILABLE` message, cache tmp wording.

### Settings card

- Live region scoped to the message strip (buttons no longer inside
  `role=status`); one conflict message plus a Retry button; loading text from
  the dictionary; read-only placeholders; per-row toggle errors for flat rows;
  no-op edits no longer stage; integer-only numeric bounds; pending badge uses
  `configured === undefined` so a known key does not flicker back to
  “checking”; credential refreshes only the event's ref.
- **Batch save**: all validated field ops go in one POST (`setMany`, route
  accepts 64); legacy hosts fall back to per-field `set`/`unset`. Credentials
  still use their own API.

## Authority corrections (audit 126 overstatements)

- Round-robin is a structural analogue of `mergeSearchResults`, not a byte
  mirror (host interleaves queries, plugin interleaves backends).
- Firecrawl/Exa limits cited from REST OpenAPI do not prove the MCP tool
  schema; treat them as B until the MCP `tools/list` schema is probed. The
  requested-limit change is still the better default.
- Parallel's “2–3 queries” is guidance, not a contract; code uses MCP, not
  REST `/v1/search`.
- URL hygiene was partial (path lowercasing could merge resources); fixed.
- Cache retention was already documented; the real gaps were no-store,
  permissions and UI disclosure.
- The RRF 2× weight prevents a known ranking failure mode; it is not evidence
  of better answer quality.
