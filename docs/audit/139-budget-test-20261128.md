# 139 — 2026-11-28 zero-variant budget and test reliability (2.13.8)

Baseline 2.13.7 (`75f779a`, 240 tests). Final **240/240** tests; 15
consecutive full-suite runs green.

- **Bug: a spent deadline before the first variant returned an empty success.**
  `searchDeadline` is set before the variant loop; under a small
  `backendTimeoutMs` (or heavy host load), the first iteration could break on
  `remaining < minVariantBudgetMs` before any backend ran. `perVariant` and
  `allTelemetry` stayed empty, and the empty-success branch returned
  `{sources:[]}` instead of an error. The loop now records a zero-result
  history entry and throws `search budget exhausted before any backend could
  run` when `variantsRun === 0`.
- **Flaky tests made deterministic.** Three timing tests raced the suite's
  parallel load: a 100 ms sync-throw timeout, a 600 ms starvation test and a
  1 ms zero-variant test. The sync test now has 5 s; starvation advances a
  stubbed `Date.now` by 1 s inside the first backend call instead of sleeping;
  the 1 ms zero-variant assertion was removed because it could legitimately
  run before or after the deadline. The zero-variant guard itself remains.
- Tests: 15× full-suite stress, 240/240 each.

Residual: the guard is exercised by production-shaped budgets rather than a
dedicated zero-variant test; a direct clock injection is not exposed.
