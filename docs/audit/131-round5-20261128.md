## Exa advanced-domain probe (closed with evidence)

Probed `https://mcp.exa.ai/mcp` with MCP `initialize` → `notifications/initialized`
→ `tools/list` (protocol `2025-06-18`, session returned). The server exposes
exactly two tools:

```
web_search_exa   { query, numResults, objective }
web_fetch_exa    { urls, maxCharacters }
```

There is no `web_search_advanced_exa`, no `includeDomains`/`excludeDomains`
field, and no category/domain parameter on the simple tool. The earlier audit
item "switch to Exa advanced MCP for domain filters" is therefore **not
implementable against the public keyless endpoint**; it is removed from the
backlog. Domain filters remain scoped to OpenAI/Anthropic, as documented.

## Fixes

- **Plan-backend fallback.** When the single primary `handlesAllVariants` call
  fails, later variants now include that backend again and retry it per facet.
  Previously a primary failure meant Parallel contributed nothing for the whole
  multi-query search. Success still costs one call; only failure falls back to
  per-variant calls.
- **Cache-hit history count.** Uses the scheme-whitelisted `safeSources.length`
  instead of the pre-filter cached array, so a tampered `javascript:` entry no
  longer inflates `resultCount`.
- **Tests:** cache whitelist count and plan fallback.

## Verified

- `tools/list` shape (above); no secret logged; session id not persisted.
- Plan fallback: first call throws, later variants call again and contribute a
  source; no duplicate sources because URL dedupe runs after merge.
- Cache hit: 2 cached entries (one javascript:) → 1 source and `resultCount:1`.
