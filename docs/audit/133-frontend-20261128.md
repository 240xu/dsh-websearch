# 133 — 2026-11-28 frontend UX fixes (2.13.2)

Baseline 2.13.1 (`2a70712`, 229 tests); expert frontend review against the
rendered card. Final **232/232** tests.

## Fixes

- **All-or-nothing Save (P1).** A batch with one invalid field (e.g.
  `numResults=12` + `cacheTtl=45`) used to POST the valid sibling, report
  "Save failed", and leave the user unsure what persisted. Validation now
  stops before any POST when `failedFields` is non-empty; the whole staged set
  stays intact for correction.
- **Cache TTL rules are visible (P1).** The field now carries
  `aria-describedby` and a hint: "Multiple of 30 s; 0 disables the cache
  (no-store)." Invalid input marks `aria-invalid` and the failure message uses
  the localized label, not the raw field id.
- **Cache switch and TTL are adjacent (P2).** `cacheEnabled` moved from the
  result-shaping grid into the globals grid immediately before `cacheTtl`;
  TTL is disabled while the cache is off and the hint says it is ignored.
- **Save focus (P1).** The Save button stays enabled after success (only
  `saving`/read-only disable it), and a no-op save returns early; keyboard
  focus is no longer dropped to `<body>` after each save. A failed validation
  focuses the first invalid input.
- **Retry outside the live region (P2).** The conflict Retry button was a
  child of `role=status`; it now sits after the status span, so screen readers
  do not announce a button as status text.
- **Parallel duplicate `objective` (P3).** Removed the first assignment; the
  planned objective wins.
- **OpenAI domain text (P3).** Config/README now say OpenAI/Anthropic both send
  one list (include wins), matching the code; removed the stale "OpenAI sends
  both" claim.

## Tests
