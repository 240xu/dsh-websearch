# 150 — multi-expert code-quality review (2.13.17)

Baseline 2.13.16 (`7cab575`, 256 tests). Six independent reviewers covered
server concurrency, client state machine, semantics, adversarial bugs,
maintainability and the full plugin; Claude Code failed before returning a
result and was replaced by a maintainability reviewer. Final **267/267** tests,
10 consecutive full-suite runs.

## P1 fixed

- **Client error deadlock**: reverting an invalid field to its saved value or
  clearing a rejected credential left `failed`/`failedFields`/`failedKeys`
  populated with no staged draft. Save then returned early while the red error
  stayed forever. Edits now clear the per-field/per-key error and `failed` when
  no error source remains.
- **Provider timeout misclassification**: `budgetClipped` used
  `remainingNow < configured - 10`, so any backend that started a few
  milliseconds late (concurrency queue) was exempt from health/breaker. A hung
  backend never accumulated failures and every search paid the full timeout
  again. Clipping now requires a material budget reduction.
- **RRF bypassed canonical URLs**: fusion keyed on raw URLs, so host case /
  `utm_*` variants and `url+title` mirrors could occupy multiple result slots.
  `rrfFuse` now uses `canonicalUrlKey`; the provider runs the configured dedupe
  policy once after fusion.

## P2 fixed

- Slider label click now restores the committed stop and cancels a drag
  preview; pointer-down and any new preview cancel a pending keyboard settle;
  the settle callback verifies the input still points at the captured tier.
- Toggle writes get a per-backend sequence so a slow failure cannot repaint
  after a newer success.
- Credential read failure leaves the configured state unknown and shows a
  "read failed" badge instead of contradictory "not set"; a successful save
  clears the read error.
- History route registration rolls back its first route if the second
  registration collides.
- Queued backends are not called after caller cancellation.
- Official hint / Config descriptions now name the full override set
  (including multi-query and deep coverage); README timeout, dedup threshold,
  numResults caps, result-header/telemetry and cache-key conditions match code.
- Removed dead client option declarations and stale comments.

## Residual P2 (documented, not changed)

- `provider.js` cache-key field knowledge is still repeated across Config,
  `resolveOptions` and the provider regex; a future field can be missed.
- Telemetry line rendering still has two similar paths.
- Legacy hosts without `setMany` do not get atomic multi-field saves.
- `enabledBackends` override is counted in the status strip but does not disable
  the per-backend toggles.
- Client test stubs do not exercise real hook re-renders; slider ref/effect
  behavior is covered by handler-level tests plus review.
