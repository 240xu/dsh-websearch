# 129 — 2026-11-28 round-3 audit fixes (2.11.0)

Baseline: 2.10.0 (`fa1555a`, 220 tests). Four experts re-audited domain filters,
Exa limits, telemetry fold and the in-flight SearXNG paging. Verification:
**225/225** tests, health 1/1, npm 2.11.0, patches 32/32 + 33/33.

## P1 / P2 fixes

- **Domain cache key (P1)**: `includeDomains`/`excludeDomains` were not in the
  cache key, so a new restriction could be served the prior unfiltered entry
  for up to 900 s. Both top-level lists and per-backend copies now enter the
  key; a regression test changes the filter between two searches and asserts
  two backend calls.
- **Domain normalization (P2)**: split on `,，、;；`/whitespace; strip `*.` and
  a trailing FQDN dot; reject empty labels and bare IPs; if a non-empty list
  normalizes to nothing, `resolveOptions.domainFilterError` makes the search
  fail with a clear error instead of silently dropping the restriction.
- **Credential presence**: a shared `keyPresence` map is updated by every
  `resolveApiKey()`; key-gated backends consult `credentialPresent` in
  `available()` and invalidate on `credentials/reference-updated`. Optional-key
  backends ignore it. A confirmed missing key therefore stops advertising the
  provider until a key appears (60 s unknown fallback).
- **Budget starvation**: a backend whose shared-budget slice is materially
  below its configured timeout is no longer pushed into breaker/health; it is
  recorded as a skipped telemetry segment. A regression test runs three
  budget-clipped searches and asserts the breaker stays at 0.
- **SearXNG paging**: two pages only for a single instance when
  `deepCoverage` is on and internal multi-query is off; dedupe across pages;
  page-2 failure/rate-limit returns page 1 and pauses pagination for 60 s;
  multi-instance failover stays at one page per attempt.
- **Batch save attribution**: client-side numeric steps mirror the server
  (`backendTimeoutMs` 1000, `cacheTtl` 30); a schema 400 naming a field marks
  that control instead of a generic save failure.
- **Provider domain semantics**: OpenAI sends exactly one of allow/block
  (include wins); Anthropic keeps include-wins; the shared DeepSeek route no
  longer gets unprobed domain fields.
- **Docs**: cache no-store/cap/0700-0600/purge, SearXNG paging conditions,
  domain scope, 225 tests.

## Authoritative checks

- OpenAI: `filters.allowed_domains`/`blocked_domains` nested in `web_search`;
  Anthropic: `allowed_domains`/`blocked_domains` on the tool and mutually
  exclusive; Exa `numResults` 10/100; Brave 20; Tavily 0–20; SearXNG `pageno`
  with JSON opt-in; DSH `dsh-web/src/types.ts:26-63` one-query contract.
- Citation provenance remains **removed from the backlog**: native backends
  discard answer text and return before the host answer exists, so URL
  membership is tautological and entailment would need the final answer plus
  fetching. Keep deterministic URL canonicalization only.
- Parallel 2–3 queries remains deferred: it would multiply calls unless the
  provider passes a plan to a backend that opts into handling all variants.

## Known residuals

- Exa advanced MCP domain filter needs a recorded `tools/list` probe.
- Parallel multi-query plan (one primary call with 2–3 queries) not wired.
- `available()` presence is a hint, not a security boundary; the key is still
  resolved per search.
- Cache hit `resultCount` uses pre-whitelist length (P3); `health.reachable`
  null now also means "attempted without a key" (P3).
