# 134 — 2026-11-28 round-6b: missing-key health and facet starvation (2.13.3)

Baseline 2.13.2 (`3d281b7`, 232 tests). Optimization review found two P2s;
final **235/235** tests.

- **`credentialMissing` survives the health fold.** `fanoutVariant` rebuilds
  each health entry, so the flag was dropped before `recordBackendHealth`;
  a missing key then cooled the backend despite the intended
  configuration-not-outage branch. The flag is now copied into the entry and
  OR-preserved across variants; `/health` reports it, breaker stays at 0.
  Regression test uses the real `braveBackend` with a missing key.
- **Two-second budgets can run three fast facets.** The per-variant floor was
  `min(configured, 2000)`, so a 2000 ms budget left no room for variants 2–3
  after variant 1 (even an 11 ms backend). Floor lowered to 1000 ms.
- **Truncated multi-query runs are labelled and not cached.** When the shared
  deadline stops later facets, the telemetry line ends with
  `multiQuery: N/M facets not run (search budget)`, and the result is not
  written to the cache (a transient slow variant otherwise degraded all
  identical searches for the TTL). Test: fast 2s budget → 3 calls; 600 ms
  budget with a 500 ms first call → 1 call + note, and the next fast search
  is not served from cache.
- Removed the now-unused local `budgetClipped` in the timeout setup.
